# P5.2 Save-driven Combat / Buff Scenarios

All saves are produced **by the original game** (no hand-edited bytes):

1. `tools/oracle/create-char.py <class>` drives the original character-creation UI → level-1 save.
2. `tools/oracle/author-save.py <spec>` loads it, raises experience with the oracle `setexp` op
   (original `PLAYER_LevelUp` `0x6FD0B090`), spends points with genuine C2S `0x3B AddSkill` /
   `0x3A AddStat` packets (the server enforces prerequisites and level requirements) and saves
   through the in-game *Save and Exit* menu. Specs: `tests/fixtures/oracle/saves/specs/*.json`.

Scenarios are generated by `tools/oracle/make-p52-scenarios.py` (seed 12345 → identical map and
route out of the Rogue Encampment for every class; first Blood Moor zombies are units 9/10/11).
Every oracle scenario was run twice and produced byte-identical traces; goldens live in
`tests/fixtures/oracle/golden/*.oracle.ndjson.gz` and are checked by
`tests/oracle/golden-parity.test.ts` (ratchet, baseline `parity-baseline.json`).

## Gaps (next scenarios)

- Mercenary auras / party auras (needs a hired mercenary → author via the original Kashya dialog).
- Item-driven defence (DR/MDR, absorb, thorns, CtC): needs saves with equipment; author by
  injecting the original `0x9x` vendor/pickup packets or via a cube/vendor flow.
- Per-frame DoT ticks that bypass `SUNITDMG_ApplyDamage` (burning ground, poison ticks) are visible
  only as defender HP (`stat6`) changes in `t1`; add a hook on the DoT tick path if per-tick events
  are needed.
