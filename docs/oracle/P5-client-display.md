# P5.4 — Client display-value differential (original 1.13c client vs TS client)

Generated by `npx tsx tools/oracle/client-ui-compare.ts <oracle-dir> --report docs/oracle/P5-client-display.md`
from the original-game capture of `tools/oracle/run-client-ui.sh` (hook `tools/oracle/hook/clientui.dll.c`,
evidence `kb/ui/oracle-client-display-113c.md`). Saves: the five original-authored level-40 characters, in town,
normal difficulty, 75 frames after the client player appears; nothing selected or cast.

**Original** = strings captured from the original D2Client draw functions (D2Win text-draw imports redirected,
no OCR). **TS** = the same save loaded into the TS server (`GameInstance`) with its events fed to a headless TS
client (`OnlineSession` → `ClientWorld` → `HudModel.syncFromWorld`), values read the way
`CharacterSheetPanel.draw` / `SkillTreePanel.formatSkillTooltipLines` render them.

Scope of the per-skill rows: every skill in the original client skill list is placed in the hand it can be
selected on (Skills.txt `leftskill`) and the attack block (name, damage, attack rating) is compared. Passive
skills (Skills.txt `passive`) and the scroll/tome skills 217..220 cannot be put on a mouse button, so their
blocks are not compared (their tooltips are).

Coverage limits: the saves wear only starting equipment and nothing is cast, so the character sheet exercises
base attributes, vitals, defense, block and attack rating but no item/buff modifiers (blue/red values,
resistances other than 0, Battle Orders max life). The AR / defense hover hit chances (0x6FB6CB90 /
0x6FB6C520) depend on the last hovered monster and are captured (`calc.hitLeft/hitRight/monHitPct`) but not
compared. A geared/buffed capture needs scenario input injection in clientui.dll (next step).

## Server resolution vs client display

Each mismatch carries a layer:

* **server** — the TS client already holds different data than the original client (stat lists compared:
  original D2Common #10973 on the D2Client player 0x6FBCBBFC vs TS `ClientWorld.self.stats`; skill lists:
  original unit+0xA8 chain vs TS `self.skills`). The TS server resolved or transmitted it differently; the
  display code is not at fault.
* **client** — the underlying client data agrees, but the TS display computation/formatting differs from the
  original D2Client function named in the cause.
